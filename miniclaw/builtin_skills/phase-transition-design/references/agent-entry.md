# 研究 agent 入口 · v0.3

任务：给出完整、可交接、可追溯的关键参数方案。优先输出具体值或有限候选，保留真正影响研究定义的未知。不要只交付待填写清单。

## 最短阅读路径

1. 读本页和[参数决策表](decisions/parameter-table.md)。
2. 只选一条：[恒温恒压/温扫](decisions/npt.md)或[拉伸](decisions/tension.md)。
3. 只选一份：[UNEP-v1 决策包](decisions/unep-v1.md)或[Pd–Cu–Ni–P 决策包](decisions/pdcunip.md)。

**首轮阅读预算就是这四页。**先形成参数包；核心页已经给出本地势身份、规则来源和能力边界，不为“再确认一遍”展开旧专题、方法页或整份资产清单。只有发现核心页缺少必需字段、相互冲突，或用户明确要求核实原文时，才按该问题读取最少的补充页，并记录触发原因。计算器按计算契约调用；调用契约不要求阅读实现源码。

交付记录实际读取的知识文件。自写回答、脚本输出和重复读取不计入知识阅读量。首轮表格尽量紧凑，公共控制参数只列一次，各阶段列差异；完整取证与详细复核可另开后续阶段。

## 输入优先级

用户已定条件 → 实际模型与运行文件事实 → 与本任务匹配的文献 → 明确标记的设计候选。用户条件冲突时指出冲突；候选不能悄悄覆盖硬约束。

输入中已有或可从文件读取的成分、尺寸、边界、初态、温压和参考信息，不重复问用户。正式弛豫后才产生的参考盒长是运行时依赖，不是必须现在问用户的缺参。

若初态、晶向或研究边界不明确：先读已有资产；仍未知时，给明确假设的基线或有限分支，最多合并询问一组会改变研究对象的问题。步长、耦合、输出间隔和候选运行长度由你专业提案，不让用户代选。

## 每个参数都带状态

`USER` 用户锁定；`FILE` 文件核实；`LIT` 匹配文献报告；`CAND` 设计候选；`CALC` 由已知量计算；`RUNTIME` 在指定上游完成后绑定；`BLOCK` 冲突/不支持、需要解决。

**按叶字段分别标记，不能给混合字典一个总状态，也不用 `CAND/CALC` 代替拆分。**已登记的势文件名/哈希为 FILE，选择它可另记 CAND/USER；物理 tau 候选是 CAND，而 tau/dt 比值和步数是 CALC。论文报告值为 LIT，本次采用该值的选择为 CAND，导出预算为 CALC。待执行检查状态另列，不混入参数来源枚举。需要细节时查[交接契约](decisions/handoff-contract.json)。

候选数值用于可执行探索，不等于已经证明材料精度。运行时字段写出取得路径和计算式，不能伪造数值。缺少材料专用验证不自动阻断有限范围的探索设计。

## 固定交付格式

1. **目标与假设**：研究对象、能回答的结论、保留的用户约束。
2. **参数表**：值、单位、状态、依据/规则 ID、验证；至少覆盖势、成分/模型、初态/晶向、N/尺寸、边界、温压/每轴约束、算法、步长、耦合物理时间、控制模量、阶段时间/步数、种子、输出和目标判据。拉伸另加应变定义、轴、速率、终点、参考及增量。
3. **闭合计算**：物理时间、步数、加载增量与输出分辨率一致。需要精确算术时可按[计算契约](decisions/calculation.md)调用已提供的只读计算器，不必读其源码。
4. **交接状态**：`DESIGN_READY` 参数已明确、可交给专业角色；`RUNTIME_PENDING` 等待正式参考/模型；`NEEDS_DECISION` 硬约束冲突；`UNSUPPORTED` 请求方法或工具未提供。状态可按阶段并存。
5. **有限验证与缺口**：初始预算、最多追加量、停止条件；未提供的统计/拟合/绘图功能单独列出，不声称已完成。

引用只用明确登记的规则、证据或来源 ID（如 `U-D02`、`U-01`、`S17`），不得把“NIST 温度表”等自由描述冒充 ID。可用[引用索引](decisions/reference-index.json)机械定位，首轮无需额外通读；每项关键参数同时保留其直接规则 ID。

不要为了“给出结果”把文献值写成本次观测，也不要因为候选尚待验证而把所有参数留空。
