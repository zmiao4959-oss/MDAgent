# 项目 Skill 开发

用 `list_skill_requests` 读取请求约束与草稿目录。在写文件前阅读 [references/package-format.md](references/package-format.md)；其中定义了发布清单、测试入口和挂载规则。

交付与具体请求相匹配的最小 Skill：入口说明何时适用、输入输出、已有工具调用方法与限制；确定性实现放在 `scripts/`，按需资料放在 `references/`。测试使用小型、已知结果的样本，覆盖验收中的正常情况和关键失败条件。

生成代码前核实请求者已有工具及职责。不能用新增包取得缺失工具权限，不能把修改角色配置、安装依赖或开发全局工具作为发布步骤。需要外部算法事实且现有材料不足时，向有相应能力且已连线的角色索取依据，明确尚未解决的依赖。

Python 测试通过 `publish_skill(request_id=...)` 在临时目录执行；无须使用 shell。失败报告是修改草稿的依据。发布后的文件具有内容指纹，修改应通过新的请求和版本完成。

返回真实状态、Skill 名称、版本、测试数量与适用范围。不要把测试成功表述为完成了原始模拟任务；原任务由挂载目标继续执行。
