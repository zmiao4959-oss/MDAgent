# MiniClaw 自我进化第二阶段任务书

## 1. 目标

把当前“文本经验注入 Prompt”的机制升级为可验证、可合成、可执行的策略系统：

1. 从工具调用中提取脱敏的语义化步骤，而不是只记录工具名顺序。
2. 将经验表达为带适用条件、操作步骤、约束、验证标准和失败回退的结构化策略。
3. 将同一任务族的多条稳定策略合成为符合 Codex 规范的 `SKILL.md` 草案。
4. 将结构化策略编译为受限工具封装；隔离测试通过并明确审批后才可启用。

## 2. 安全边界

- 完整 Trace 继续保存在项目目录；全局库只保存脱敏语义。
- 不把密钥、完整文件内容、绝对项目路径或任意 shell 文本写入全局策略。
- 结构化策略只能提供建议，不能覆盖用户指令、权限和安全规则。
- Skill 草案不得自动覆盖已安装 Skill。
- 可执行策略默认是草案；必须通过静态检查、隔离测试和明确审批。
- 可执行策略只调用允许的工具，路径必须位于指定工作区，命令必须通过危险模式检查。
- 本轮开发节点由 Codex 根据测试结果审批；产品运行时的 Skill/可执行策略审批仍保留显式确认。

## 3. 数据模型

### 3.1 语义步骤

每个步骤至少包含：

- `tool`：原始工具类别。
- `action`：`read`、`write`、`execute`、`search`、`inspect`、`transform`、`verify` 等语义动作。
- `intent`：对该步骤目的的脱敏描述。
- `resource_type`：文件或数据类型，例如 `yaml-config`、`python-source`、`lammps-input`。
- `command_family`：执行类步骤的命令族，不保存完整命令。
- `constraints`：工作区、只读、允许扩展名等限制。
- `success_signals` / `failure_signals`：可观察的结果类别。

### 3.2 结构化策略

策略采用可序列化 JSON，包含：

- `schema_version`
- `task_pattern`
- `conditions`
- `steps`
- `validation`
- `fallback`
- `safety`

经验指纹升级为“任务模式 + 语义步骤签名”。旧经验继续可读，缺少结构化策略时回退到文本经验。

### 3.3 Skill 草案

- 同一任务模式至少两条已验证经验才允许合成。
- `SKILL.md` frontmatter 只包含 `name` 和 `description`。
- 正文使用命令式表达，包含条件、工作流、验证、回退和安全边界。
- 不生成 README 等无关文件。

### 3.4 可执行策略

每个草案包含：

- `policy.json`：允许的步骤、参数约束、前置条件和后置验证。
- `runner.py`：固定模板的受限运行入口，不包含经验生成的任意代码。
- `metadata.json`：来源经验、测试状态和审批状态。

审批后安装到全局工作区的 `.miniclaw/evolution/executable-policies/approved/`。

## 4. 实施阶段与验收

### 阶段 15：语义化步骤与结构化策略

任务：

- 新增确定性、脱敏的语义步骤提取器。
- 扩展经验数据库并兼容旧库。
- 用语义签名生成新经验指纹。
- 在 Prompt 中渲染条件、步骤、验证和回退。
- 面板展示结构化步骤摘要。

验收：

- 相同工具顺序但不同资源/命令族不会错误合并。
- 绝对路径、密钥和完整命令不会进入全局策略。
- 旧经验数据库能无损迁移。
- 结构化策略能够被检索并注入其他项目。

Git 节点：`阶段15：语义化经验与结构化策略`

### 阶段 16：稳定经验合成 Skill 草案

任务：

- 从多条已验证结构化经验合并工作流。
- 对重复步骤去重，对冲突条件进行标记。
- 自动生成待审草案，不自动安装。
- 扩展静态验证和隔离测试。

验收：

- 少于两条已验证经验不能合成。
- 草案符合 Skill 命名、frontmatter 和篇幅规范。
- 草案包含条件、步骤、验证、回退和安全边界。
- 冲突、危险指令或覆盖已有 Skill 时审批失败。

Git 节点：`阶段16：结构化经验合成技能草案`

### 阶段 17：受限可执行策略

任务：

- 从结构化策略生成声明式 `policy.json` 和固定 runner 模板。
- 实现工具、路径、参数和危险命令校验。
- 在临时工作区使用假工具执行隔离测试。
- 实现草案、测试、审批、拒绝和版本记录。

验收：

- 未审批策略不可运行。
- 越界路径、网络工具、未知工具和危险命令被拒绝。
- 隔离测试失败的策略不能审批。
- 精确确认后才能安装，且不得覆盖同名策略。
- 合法策略可按声明顺序调用受限执行器并验证结果。

Git 节点：`阶段17：受限可执行策略与隔离审批`

## 5. 回归要求

- 每个阶段新增独立的 `tests/test_*.py`。
- 每个阶段新增 `scripts/acceptance_stage15.py` 至 `acceptance_stage17.py`。
- 每个阶段先跑针对性测试，再创建 Git 节点。
- 最终运行全部 Pytest、阶段 1–17 验收、前端语法检查和 `git diff --check`。

## 6. 回滚策略

- 每一阶段对应独立 Git 提交，可单独回滚。
- 数据库只做向前兼容的加列/加表，不删除旧字段。
- 新策略字段为空时继续使用旧文本经验。
- 可执行策略安装前保留草案，拒绝不会删除审计材料。
