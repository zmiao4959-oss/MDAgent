# MiniClaw 单候选 PR 型源代码自进化计划书

## 1. 目标

建立一个不修改正在运行实例、可审计、可测试、可回滚的源代码改进闭环：

```text
重复失败 → 改进提案 → 独立 Git worktree → 先写复现测试
→ 生成补丁 → 受保护评估 → 候选提交 → 明确晋升 → 可恢复回滚
```

本阶段一次只允许一个候选实验，暂不进行多候选演化搜索。

## 2. 核心原则

- 运行中的 MiniClaw 不直接覆盖自身源代码。
- 所有改动只发生在独立 Git worktree 和 `codex/evolution-*` 分支。
- 必须先生成能够在旧实现上失败的复现测试，再允许修改实现代码。
- 候选不得修改评估器、安全边界、Git 晋升逻辑或测试门禁。
- 候选必须通过新增测试、全量测试和静态安全检查。
- 晋升使用 Git 提交和非快进合并；回滚使用 `git revert`，禁止硬重置。
- 每个实验保存提案、证据、diff、命令、测试结果、评分和 Git 标识。
- 本轮开发阶段由 Codex 根据自动验收批准；产品运行时的源代码晋升仍要求明确确认。

## 3. 数据模型

### 3.1 源代码改进提案

`SourceProposal` 包含：

- 提案 ID、标题、问题签名和状态。
- 产生问题的 Trace、项目和错误分类。
- 可疑文件和受影响模块。
- 修改假设、预期收益、风险及回滚说明。
- 创建时间、更新时间和关联实验 ID。

相同问题签名只保留一个开放提案，避免重复修复。

### 3.2 源代码实验

`SourceExperiment` 包含：

- 实验 ID、提案 ID、基线提交和候选分支。
- worktree 路径。
- 新增复现测试及其“修改前失败”证据。
- 实现补丁、变更文件和 diff 统计。
- 针对性测试、全量测试、静态检查和风险结果。
- 候选提交、晋升提交、状态及失败原因。

## 4. 受保护范围

候选默认禁止修改：

- `.git/`、Git hooks 和工作流门禁。
- `miniclaw/learning/source_evolution.py` 自身。
- 权限、密钥、治理、备份和清除逻辑。
- 全量测试入口、评分器和晋升阈值。
- `tests/` 中已有测试；允许新增专属回归测试，但不允许删除或弱化旧断言。
- `scripts/acceptance_stage*.py` 中已有验收脚本。

补丁还受以下限制：

- 变更文件数、总增删行数和单文件大小上限。
- 禁止二进制文件、子模块、符号链接和仓库外路径。
- 禁止新增网络下载、动态执行、反序列化和绕过审批代码。

## 5. 阶段划分

### 阶段 18：重复缺陷检测与提案库

任务：

- 聚合所有项目的失败 Trace。
- 对错误进行脱敏、数字归一化和类别归并。
- 只有达到最小次数和项目多样性后才生成提案。
- 从 Python 堆栈中提取仓库内可疑文件，不保存外部绝对路径。
- 使用 SQLite 保存提案和状态历史。

验收：

- 三个匹配失败、来自至少两个项目时生成一个提案。
- 重复扫描不生成重复提案。
- 密钥和仓库外路径不会进入提案。
- 未达到门槛的问题不生成提案。

Git 节点：`阶段18：重复缺陷检测与源代码提案`

### 阶段 19：测试优先的隔离补丁实验

任务：

- 从干净基线创建 `codex/evolution-<id>` 分支和独立 worktree。
- 通过受限补丁代理接口生成复现测试。
- 验证测试在未修改实现时确实失败。
- 再允许补丁代理修改实现代码。
- 检查受保护文件、变更规模、测试弱化和危险代码模式。

验收：

- 实验不会修改主工作区。
- 复现测试未失败时实验被拒绝。
- 修改受保护文件或越过变更预算时实验被拒绝。
- 合法补丁保留完整 diff 和测试证据。

Git 节点：`阶段19：隔离测试优先的源代码实验`

### 阶段 20：评估、候选提交、晋升与回滚

任务：

- 运行针对性测试、全量 Pytest、前端语法和差异检查。
- 记录测试数量、耗时、风险、改动规模和综合评分。
- 评估通过后只提交候选分支，不自动合并。
- 使用精确确认晋升候选；要求主分支仍处于原基线且工作区干净。
- 使用 `git revert` 创建可审计回滚提交。
- 提供服务层和管理 API 查询提案、实验、评估、晋升和回滚。

验收：

- 测试或安全检查失败的候选不能提交和晋升。
- 未精确确认、主分支漂移或脏工作区时不能晋升。
- 晋升生成独立合并提交，源分支和实验记录可追踪。
- 回滚生成 revert 提交并恢复基线行为。

Git 节点：`阶段20：源代码候选评估晋升与回滚`

## 6. 补丁代理接口

源代码进化框架不绑定具体模型。补丁代理必须实现两个阶段：

1. `write_reproduction_test(worktree, proposal)`：只允许新增测试文件，返回测试命令。
2. `implement_patch(worktree, proposal)`：在复现测试确认失败后修改允许的实现文件。

框架负责 Git、安全、测试和晋升；模型只负责提出测试和补丁，不能决定自己是否通过。

## 7. 自动审批矩阵

可以由固定门禁自动批准为“候选提交”：

- 新增回归测试。
- 小范围实现修复。
- 学习、检索、UI 和非权限工具内部的低风险改动。
- 全量测试通过且无受保护文件变更。

仍需产品运行时明确确认才能合并：

- 所有源代码候选，即使评分通过。
- 涉及 Agent 主循环、工具执行或配置加载的中风险改动。

受保护模块不接受单候选自审批，必须由未来的外部审查器或人工流程处理。

- 每个阶段创建独立 Git 提交，工作区最终保持干净。
