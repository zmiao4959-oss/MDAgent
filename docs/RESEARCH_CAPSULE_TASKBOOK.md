# 科研胶囊阶段 24–26 任务书

## 目标

把一次科学计算从“聊天记录加散落文件”提升为可检查、可迁移、可验证、可安全重放的研究资产。科研胶囊必须服务于复现，而不是绕过 MiniClaw 已有的工作区隔离、审批和审计边界。

## 不变量

1. 胶囊默认只保存在项目工作区，不自动上传或分享。
2. 只记录工作区内的普通文件；拒绝符号链接和路径逃逸。
3. `.env`、私钥和常见凭据文件不得进入文件清单。
4. 工具参数中的密钥字段、Bearer token 和内联密钥必须脱敏。
5. 胶囊生成期间项目必须停止运行，避免记录不稳定文件。
6. 重放不得覆盖原工作区；必须先预览并要求精确确认。
7. 文件完整性以真实磁盘字节的 SHA-256 为准，不做换行或编码归一化。

## 阶段 24：捕获与持久化

状态：已实现并通过完整回归验收。

交付内容：

- `ResearchCapsule` 与 `CapsuleFile` 数据模型。
- 按相对路径稳定排序的文件清单、逐文件 SHA-256 和总清单摘要。
- 项目目标、对话统计、最近一次 Evolution Trace、Python/平台/关键依赖和 MiniClaw Git 状态。
- 对敏感文件、符号链接、工作区外路径和捕获期间变化文件的排除记录。
- 项目本地 `.miniclaw/research-capsules/<capsule-id>/capsule.json` 与 `README.md`。
- 项目级创建、列表和详情 API；胶囊创建写入项目时间线。

验收标准：

- 同一组未变化文件生成相同 `manifest_sha256`。
- Windows 与 Unix 换行均按实际字节正确校验。
- 生成物不包含测试中的密钥明文。
- `.miniclaw` 运行状态不递归进入胶囊。
- 非隔离项目工作区和正在运行的项目不能生成胶囊。

## 阶段 25：验证、导出与界面

状态：已实现并通过完整回归验收。

交付内容：

- 对当前工作区执行 `verified / changed / missing / unreadable` 完整性验证。
- 生成只读验证报告，列出新增、修改、缺失和跳过文件。
- 导出前二次脱敏，生成可迁移 ZIP；大文件支持仅清单模式。
- WebChat 项目页增加“科研胶囊”面板、状态徽标和下载入口。
- v1 schema 保持不变；验证和导出证据使用独立文件，旧 v1 胶囊仍可读取。

精确确认：导出包含实际文件时要求 `EXPORT <capsule_id>`。

## 阶段 26：隔离重放

计划内容：

- 从胶囊创建新的隔离工作区，不修改原项目。
- 重放前检查运行时、依赖、输入哈希、可执行工具白名单和资源预算。
- 从 Trace 生成可审计的重放计划；默认不执行网络、通信和任意 shell。
- 用户预览差异后输入 `RERUN <capsule_id>` 才能执行。
- 重放结果生成派生胶囊，并记录父胶囊、差异和验证结论。

## 数据模型 v1

`capsule.json` 顶层字段：

- 身份：`schema_version`、`capsule_id`、`project_id`、`chat_id`。
- 研究语义：`title`、`objective`、`created_at`、`status`。
- 证据：`conversation`、`trace`、`environment`、`source`。
- 完整性：`files`、`skipped_files`、`manifest_sha256`、`file_count`、`total_bytes`。

文件记录包含 `path`、`size`、`sha256`、`modified_at`。`manifest_sha256` 只对稳定字段 `path/size/sha256` 的规范 JSON 计算，因此不受 mtime 和胶囊创建时间影响。

## 风险与后续决策

- 分子动力学轨迹可能达到数十 GB。当前提供仅清单导出，但完整导出仍需要增加进度、取消、资源预算和外部对象存储引用，不能让 API 长时间无反馈。
- 工具参数和 UTF-8 文本脱敏只能阻断已知模式；二进制文件不会被内容改写。后续应增加可配置内容扫描器和导出排除项预览。
- 当前 Git 状态反映 MiniClaw 源码，不代表远程模拟环境；阶段 26 需要为 SSH/调度器增加独立环境描述器。
