# 工具与状态契约草案（未实现、未启用）

本文件描述批准后应开发/调整的接口。下文新工具名均为建议名称，不代表当前可以调用。它们服务于不同材料的双固相竞争；Ti、1050 K、Mao 取向属于按需实验配方，不写进通用运行服务。

## 1. 当前实现可以复用什么

以 2026-10-24 工作区为准，已有七个顶层角色：coordinator、researcher、model-worker、gpumd-generator、simulation-runner、postprocessor、skill-builder。

| 组件 | 可复用能力 | 当前限制 |
|---|---|---|
| phase-transition-design | 来源分级、参数/步数/速率闭合、有限预算和交接 | Skill 定位为 NPT、温度路径与周期 bulk 拉伸；共存制备和自由能工作流尚未建立 |
| model-worker / Atomsk | 单晶、扩胞、转换，运行已有建模 helper | 当前只授予 atomsk；没有受控双相匹配和双界面验收 |
| generator | GPUMD 输入、独立试跑、部分衔接 helper | 拉伸流程不能直接当固固界面流程 |
| 专用后处理 | FCC/HCP/BCC/ICO 全局比例、能量、体积、RDF、MSD与摘要 | 未输出逐原子空间分类、双界面位置或迁移速度 |
| SimulationService / RunStore | SQLite 作业状态、输入哈希、原子提交、调度器查询 | 不具备实验级科学门槛；远端成功主要验证调度状态和文件存在 |
| 远端后端 | SSH、Slurm/LSF、输入上传、日志尾 | 尚无结果自动回收或远端同版分析入口；可用标志不是实际连接/GPU检测 |
| AgentGraph | 角色路由、Skill 请求与消息事件 | 消息队列与当前运行在内存，不是跨重启实验状态机 |
| ProjectSkill | 测试、不可变 digest、请求者专属挂载、版本发布 | 需要正确权限和画布连接；不能以挂载绕过角色职责 |

主要源码依据（均为当前文件）：

- `miniclaw/builtin_skills/phase-transition-design/SKILL.md` 与 `references/common/capabilities.md:25`。
- `miniclaw/tools/postprocessing.py:226` 的分类计数与其输出列。
- `miniclaw/skills/project.py:193` 的 requester 权限/测试检查，`:238` 起的发布与挂载。
- `miniclaw/agents/graph.py:148` 的双向连接/read_skill要求；`:252` 起的内存路由状态。
- `miniclaw/simulation/store.py:15`、`service.py:230` 起的持久运行和提交；`remote.py:54` 起的上传、状态/日志接口。
- `miniclaw/tools/simulation_tools.py:39` 的配置级 availability 检查。

当前 hpc/sugon 配置均未启用，远端程序和环境尚未验证。本方案不假定任何 GPU 型号、GPUMD 性能或 SSH 可用性。

## 2. 最小新增能力与部署方式

### 2.1 build_phase_bicrystal：受控建模 helper

建议先封装为 model-worker 的已测试项目 Skill；有稳定 API 后可注册专用工具。

输入：

- `case_spec` 与签名/版本；两个相的同势、同温度参考晶胞及来源。
- 晶相、平面/方向、界面法向、整数匹配上限、允许应变、层厚。
- 两个界面的 registry/终止面、公共面内尺寸和应变分配策略。

输出：

- `model.xyz`、`model_manifest.json`、两相原子身份/核心初始标签和生成记录。
- 正交/手性检查，整数匹配、应变张量、原子数、最小距离（包括 PBC 接缝）、两个界面位置、密度、输入/输出哈希。
- `READY` 或明确的几何拒绝类别；失败不得偷偷放宽应变、删大量原子或改取向。

开发可借鉴本地 `PhaseTransition/script/bicrystal-fe/find_ratio.py` 和 interface-master 的方法，但旧 Fe/LAMMPS/EAM 示例、温度和经验值不直接复用。所有构建在专属目录，防止 InterfaceMaster 覆盖 POSCAR 等文件。

测试：方向/法向和右手性，原子数与密度，双接缝最小距离，跨 PBC 一致性；给定参数/版本重建一致。几何测试不能称为相变物理验证。

### 2.2 analyze_phase_interface：专用空间分析工具

建议注册给 postprocessor，保持其无通用 execute 权限。分析 worker 可在服务器部署同版实现。

输入：`run_id`、轨迹和 model_manifest；相对、法向、帧/时间区间、结构分类方法、阈值/基线、空间分箱、平滑和拟合规则。只接受该 run 的有来源产物。

必需功能：

1. 解析每帧晶胞、时间、原子身份。固定行对应只能在目标程序/输出顺序已经验证且无外部重排时使用；原子数/顺序变化时停止。
2. 逐原子结构类型和分类质量；对纯相热化样本进行同参数校准，保留未分类区。
3. 在约化/共移动坐标下构造法向结构剖面，再结合当帧晶胞给出物理位移，分离盒子应变和整体漂移。
4. 周期域中分别定位、关联并展开两条界面；记录界面宽度、横向粗糙度与局部前沿。不可用“相层厚度变化除以二”代替各界面的独立跟踪。
5. 保留相核心的空间连通性；区分界面推进、体内同步转变和界面弯曲/破碎。
6. 速度拟合使用明确的稳态窗口与区块统计，避开准备、释放瞬态和相层耗尽/碰撞。输出方向、单位、窗口、样本数与置信区间；不足时只报告位移。
7. Other/高 MSD 不直接命名为液体；用局部核心结构、位移与密度/能量共同检查。若 ω 等竞争结构无法排除，返回不可判定或转交有依据的已批准分析，不编造标签。

输出文件：

```text
phase_fractions.csv
phase_profile.h5 或等价可流式格式
interfaces.csv
interface_velocity.json
quality_flags.json
interface_position.png
phase_space_time.png
representative_frames/ + 结构着色动画
analysis_manifest.json
```

工具返回小型 summary 和文件路径，不把逐原子表、整份轨迹或二维大表塞给 LLM。

测试必须包括：已知速度的合成移动前沿、整体平移、盒子伸缩、周期穿越、两界面不等速、热噪声、粗化、体相整体翻转、身份打乱、缺时间、界面相撞。仅全局比例正确不算通过空间分析测试。

### 2.3 analyze_gpumd_thermo：统一数值口径

与现有后处理摘要复用公共解析模块；明确处理多段重复表头、时间轴、步数/重启、单位、盒子矩阵和六分量应力。

输入绑定 run/stage 与数据采样契约；输出统计、时间序列、异常和 provenance。不能把物理时间仅按“文件行号×间隔”推断，不由代理计算极值、应力均值或盒子体积。

### 2.4 collect_simulation_artifacts：远端数据闭环

输入：`run_id`、白名单相对路径/产物种类、体积预算、目的项目和恢复令牌。

- 查询/抓取明确绑定的作业目录，禁止路径逃逸和任意 SSH 命令。
- 支持续传、大小/哈希核验、临时文件完成后原子发布；原始文件与派生结果分别标记。
- 优先远端同版 analysis worker 生成小型摘要和代表帧；需要完整轨迹时单独收回。
- 返回 `AVAILABLE / INCOMPLETE / TRANSFER_FAILED`；不把远端 job 完成等同于本地数据齐备。
- 保存原始远端轨迹的清单、位置和校验信息。未经授权不自动清理原始数据。

### 2.5 probe_phase_backend：实际能力探测

在批准部署后验证非交互连接、调度器、GPUMD 版本/构建、GPU、NEP 格式、Python/OVITO依赖、输入上载、提交查询和结果取回。探测分为只读检测和明确授权的最小运行检查，后者不能伪装为只读。

返回能力报告和版本指纹。没有该报告，不能把配置里的 available=true 当成 G0 通过。

### 2.6 validate_phase_case / summarize_phase_campaign

程序化检查 case 字段、范围、依赖、数据与状态，按预注册判据出具证据表。科学解释仍由专家给出，数值检查和状态不能由自由文本覆盖。

## 3. 实验级契约

下面是数据结构示意，不是可直接执行的现有配置：

```json
{
  "schema_version": "proposal-1",
  "campaign_id": "ti-hcp-bcc-demo",
  "goal": "reproducible_seeded_interface_growth",
  "potential": {"asset_id": "unep-v1-main", "sha256": "8f97c30c..."},
  "phases": ["hcp", "bcc"],
  "geometry": {
    "orientation_id": "mao-ti-v1",
    "normal_axis": "z",
    "periodic": [true, true, true],
    "expected_interfaces": 2,
    "reference_cells": "RUNTIME:bulk-calibration"
  },
  "conditions": {"temperature_K": 1050, "boundary_protocol": "orthorhombic-zero-target-normal-pressures"},
  "stop_after": "interface_evidence_report",
  "stages": ["bulk", "build", "prepare", "release", "production", "analysis"],
  "budget": {"max_physical_cases": 18, "max_smoke_runs": 4, "max_total_time_ns": 6},
  "scope_changes_require_new_spec": true
}
```

正式 schema 每个参数叶字段保留现有 USER/FILE/LIT/CAND/CALC/RUNTIME/BLOCK 来源状态、单位、依据、依赖和是否必需；不把一个字典的总标签代替逐字段来源。SHA 必须完整，示意省略号不得进入正式任务。

近吞并的主指标固定为 HCP 连通相层物理体积/当帧全盒物理体积，分母包含 Other 与未分类区；原子数比例、核心区比例和已分类样本比例只作辅助指标，不能替换主指标。定位或竞争相不确定度过大时不能判通过。

物理条件、取向、势或边界改变创建新 case/version；运行恢复复用旧 case 和 run_id。种子与尺寸变化是预授权的新 case，不与旧运行混写。运行前冻结输入和软件版本，已验证后修改文件会使对应 gate 失效。

## 4. 持久状态与自动化边界

建议新增小型 SQLite campaign/case/stage 表，复用现有 RunStore，不用 AgentGraph 的内存队列充当长时实验数据库。

```text
DRAFT → SPEC_VALIDATED → BACKEND_READY → BULK_VALIDATED
→ MODEL_VALIDATED → INPUT_VALIDATED → PREPARED
→ SUBMITTING → PENDING/RUNNING/UNKNOWN
→ PROCESS_FINISHED → ARTIFACTS_READY → ANALYZED
→ GROWTH_CONFIRMED / NO_MIGRATION / INCONCLUSIVE / INVALID_CASE
```

`FAILED / BLOCKED / CANCELLED` 分开记录原因。代理回合结束不是任何一项科学终态。

- 每次推进使用预期旧状态与版本的原子更新，保留事件/决定理由。
- 重启后先恢复 case-stage-run 映射，查询原调度任务，继续等待/收集；UNKNOWN 和等待超时不创建新作业。
- case＋stage＋输入指纹是业务幂等键；“同一提示词重复派遣”的去重不能替代它。
- 仅在预注册温度、取向、种子、尺寸和累计预算内自动推进；达到预算停止，保留无迁移和失败样本。
- 模型返回 DSML/伪工具文本时标为协议异常并受控重试，不直接执行正文，不记 stage 完成。
- phase case 审批一次即可执行其预算内阶段；每一步不重复要求用户确认。换势、改变研究目标或扩大预算需另作可审阅修订。

上一条是待实现的授权契约。当前 `miniclaw/tools/registry.py:164` 对 require_approval 只记录尚未强制执行的警告，不能当成已有的预算控制。建议保存由可信用户交互产生、LLM 无权自行写入的持久授权记录，绑定 campaign/spec_hash、阶段、条件范围、预算和授权版本；submit/advance 在执行前原子核对并计入预算。LLM 文本、工具参数中的 approved 布尔或 agent 自称已授权都不能代替该记录。运行时测得的晶胞等 RUNTIME 绑定追加到可追溯的 stage 记录，不修改已批准的用户条件。

建议失败类别：`INPUT_INVALID`、`GEOMETRY_INVALID`、`BULK_UNSTABLE`、`BACKEND_UNAVAILABLE`、`PROCESS_FAILED`、`ARTIFACT_INCOMPLETE`、`CLASSIFIER_UNRESOLVED`、`BULK_TRANSFORMATION`、`INTERFACE_PINNED_OR_UNRESOLVED`、`POSSIBLE_MELTING`、`BUDGET_EXHAUSTED`、`PROTOCOL_ERROR`。没有迁移不是自动的软件故障，也不是自动的热力学平衡。

## 5. 逐项验收与独立复核

最终报告从 case 的结构化状态生成完成清单，保持 pipeline、process、artifact、science 四层状态。

- 推进证据：两个前沿的位置/形态，局部连续变相，排除 COM 和 cell 变化。
- 数值可信度：纯相分类基线、未知结构、应力、时间步长和尺寸。
- 重复性：预注册种子全部呈现，不挑成功片段。
- 结论范围：某势、边界、温度、尺寸和时间窗下的界面长大；首轮不声称精确实验相图或无约束体相 Tc。

可以由同一 researcher 在隔离上下文读取只读 evidence_bundle 做科学复核，也可后续配置只读 reviewer；不要为了首轮增加多轮全员会诊。硬门槛仍由工具执行，复核者无法把缺失数据改成通过。

## 6. 实施顺序（仅供审批）

1. 固定当前版本、部署预检和最小 schema；不更换模型来混淆基线。
2. 开发并测试双相 builder、thermo 和空间界面分析；先用合成数据验证科学判据，再接真实轨迹。
3. 补远端回收/分析与 campaign 状态；做服务重启/超时/断网恢复测试。
4. 按提示词草案调整现有角色，发布明确版本的固固共存 Skill/配方，不把 Ti 数值写进所有角色。
5. 经批准启动 G0–G3；通过后再执行独立重复与尺寸检查。

工程单元测试通过、输入试跑通过和真实材料目标通过，分别验收。当前方案尚未实现上述新增接口。
